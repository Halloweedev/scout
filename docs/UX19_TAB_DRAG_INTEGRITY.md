# UX 19 — Tab Drag Integrity

Scout treats tab dragging as one reversible interaction, commits completed reorder operations into App-owned tab state, and keeps closed-tab history under one canonical owner.

## Contract

- `navigation-ux3.ts` is the sole owner of closed-tab history through the persisted `scout.closed-tabs.v1` stack.
- Every normal close path converges through the existing tab close control, allowing UX3 to record the closing tab once before removal.
- Cmd/Ctrl+Shift+T, the `Reopen Closed Tab` command, and the tab context menu read the same persistent closed-tab stack.
- `tab-drag.ts` must not keep a second hidden closed-tab stack or intercept reopen independently.
- A tab drag becomes active only after the existing pointer-distance threshold is crossed.
- At drag start, Scout snapshots the current visual tab order.
- Pointer cancellation, Escape during a drag, and HMR teardown restore that start order instead of leaving a half-applied rearrangement.
- Releasing a dragged tab back in its starting order is a no-op and does not emit `scout:tabs-reordered`.
- A completed drag continues to suppress the incidental click that would otherwise activate the dragged tab on pointer release.
- DOM mutations generated by tab reconciliation are exact-order checked and drained from the observer so reconciliation cannot sustain its own mutation loop.
- Tabs created while a cancellation is being resolved are retained after the restored start-order tabs rather than being removed or invented by the drag layer.

## State ownership

- `App.tsx` remains authoritative for the canonical `tabs()` collection, active tab, paths, history, close behavior, and persisted tab session.
- Each rendered tab exposes its App-owned identity through `data-tab-id`.
- `tab-drag.ts` owns only the direct-manipulation preview while the pointer gesture is active.
- After a real completed reorder, `tab-drag.ts` emits `scout:tabs-reordered`.
- App reads the resulting DOM order by `data-tab-id` and commits that order into `setTabs()`. Session persistence therefore records the same order the user sees.
- Cancelled and no-op drags never reach the App state commit path.
